# commonnet.work вместо GeoHide: что сделано и как откатить

Дата работ: 8 ноября 2026. Машина: Windows 10 (19044), адаптер Ethernet, системный DNS — `192.168.1.1` (роутер).
Сервис: **https://dns.commonnet.work/** — проект ASTRACAT ([github.com/ASTRACAT2022/host-DNS](https://github.com/ASTRACAT2022/host-DNS)),
наследник схемы xbox-dns / GeoHide.

---

## Коротко

Прописать `dns.commonnet.work` как DNS **невозможно**, поэтому включена их вторая схема —
прокси-IP `217.60.179.6` в `hosts`. Правила NRPT от GeoHide удалены полностью.

## Почему не как DNS — две независимые причины

1. **Сервис работает только по DoH/DoT.** В их README два способа подключения:
   `https://dns.commonnet.work/dns-query` (DoH) и `dns.commonnet.work` (DoT).
   Обычный DNS на порт 53 у них закрыт — проверено, молчит.
   А Windows 10 (build 19044) в правилах NRPT умеет **только обычный DNS**:
   DoH/DoT-серверы там поддерживаются начиная с Windows 11.
2. **Их IP с этой сети недоступен.** `dns.commonnet.work` → `94.181.44.39`
   (PTR — `astracat74.ru`, то есть их же железо). Порты 53, 443, 853 — все таймаут,
   ICMP не отвечает, трасса умирает у ЭР-Телекома после 10-го хопа
   (`lag-1-436.bsr02.chel.ertelecom.ru`). То есть даже через DoH до них сейчас не достучаться.

Замеры (8 ноября 2026):

| Проверка | Результат |
|---|---|
| `dns.commonnet.work` A / AAAA | `94.181.44.39` / `2a12:bec4:1280:1f0::2` |
| TCP 53 / 443 / 853 до `94.181.44.39` | таймаут по всем трём |
| `https://dns.commonnet.work/dns-query` | таймаут |
| `https://commonnet.work/` (сам сайт) | порт 80 отвечает 301, HTTPS даёт TLS-ошибку |
| IPv6 на адаптере | выключен (`Get-NetAdapterBinding` → tcpip6 = False) |

## Ограничения, которые надо знать

* **В Chrome должен быть выключен «Безопасный DNS»**. Браузер со своим Secure DNS резолвит
  мимо Windows и мимо `hosts` — тогда обход не действует.
* Это обход **только геоблокировок**. rutracker, tor, Telegram API — не лечатся.
* Трафик и cookies идут через их прокси — бесплатный чужой сервис, может умереть как xbox-dns.
* Один IP на 26 доменов: если прокси ляжет, отвалятся ровно эти сайты, а не сеть.
* Их DNS-сервер (`dns.commonnet.work`) может однажды ожить — тогда честный вариант через
  локальный DoH-клиент (`dnscrypt-proxy`) станет возможен. Пока он недоступен.

## Файлы

* `commonnet.ps1` — управление: `-Show` (посмотреть), `-Apply` (включить), `-Revert` (выключить).
  Лог — `commonnet-log.txt`. Файл сохранён **с BOM** — без него Windows PowerShell 5.1 читает его
  как ANSI и русский текст превращается в кашу (на этом уже спотыкались в `geohide-nrpt.ps1`).
* `hosts-backup-commonnet-<дата>.txt` — снимки `hosts` до каждой правки.
* `nrpt-backup-commonnet-20261108-214752.json` — правила NRPT до удаления.
  Вернуть: `commonnet.ps1 -Revert -RestoreNrpt nrpt-backup-commonnet-20261108-214752.json`
* `geohide.md` — предыдущая схема (GeoHide), оставлена как история.

## Откат целиком

```powershell
powershell -ExecutionPolicy Bypass -File C:\Tools\ai-bypass\commonnet.ps1 -Revert
```

После этого ChatGPT/Gemini/Spotify снова резолвятся через роутер — для ChatGPT это заглушка ТСПУ
`8.47.69.0` / `8.6.112.0`, то есть он перестанет открываться. Для отката NRPT к GeoHide добавьте
`-RestoreNrpt`.

## Мои ошибки в этой работе

1. **Первый вариант отката затёр `hosts` в ноль.** В скрипте стоял `Set-Content -Value $new`
   с нарезкой массива по номерам строк — запись упала с `Stream was not readable` уже после
   того, как файл был открыт на запись (то есть обнулён). `hosts` восстановлен из бэкапа сразу,
   потерянных данных нет. Что сделано, чтобы не повторилось: вырезание идёт по явному циклу
   по номерам строк, запись через `[IO.File]::WriteAllLines` с ASCII, и стоит защита —
   если после вырезания осталось меньше 5 строк, скрипт отказывается писать.
   Проверено круговым тестом: `-Revert` (52→23 строки, блок ушёл) и `-Apply` обратно.
2. **Повторный `-Apply` наращивал пустые строки** (51→52→53). Исправлено: пустые строки в хвосте
   срезаются перед вставкой блока. Проверено двумя прогонами подряд — 51 строка стабильно.

# Приложение AiBypass (8 ноября 2026)

Маленький exe на рабочем столе: `C:\Tools\AiBypass.exe`.
Нужен ровно для одного: когда сервис сдохнет - за минуту подставить новый адрес, не лазя в файлы руками.

## Как пользоваться, когда обход отвалился

1. Запустить `AiBypass.exe` (спросит права администратора - это нормально, без них `hosts` не правится).
2. Нажать **«Взять из GitHub»** - программа сама скачает свежий список сервиса и подставит актуальный адрес.
   Если сервис переехал и в репозитории пусто - вписать адрес нового прокси руками в поле.
3. Нажать **«Проверить адрес»**. В логе будет по каждому сайту: `200` = пускает, таймаут = не пускает.
   Проверка ничего не меняет в системе - это замер напрямую к указанному адресу.
4. Если пускает - **«Применить»**. Всё, обход снова работает.
5. Если новый сервис даёт не прокси-IP, а **DNS-серверы** - вписать их в нижнее поле и нажать
   «Поставить правила» (это те самые правила NRPT, на которых работал GeoHide).

**Выключить совсем** - кнопка «Выключить обход (снять hosts)».

## Что внутри

* Один файл, 24 КБ, .NET Framework 4.8 (стоит в Windows по умолчанию), ничего ставить не надо.
* Правит `hosts` между маркерами `# ai-bypass BEGIN` / `# ai-bypass END` - чужие строки не трогает.
  Прежний блок `# commonnet-bypass` тоже распознаёт и заменяет своим (проверено: 51 строка до и после).
* Перед каждой записью кладёт копию `hosts` в `app\backup\`, держит последние 10.
* Список доменов (26 штук) зашит в саму программу - от интернета не зависит.
* Есть консольный близнец `AiBypass-cli.exe` для проверки без окна:
  `--state`, `--check <ip>`, `--apply <ip>`, `--off`, `--github`, `--nrpt-set <ip1,ip2>`, `--nrpt-off`.

Исходник: `app\AiBypass.cs`, манифест: `app\app.manifest`.
Пересобрать:

```powershell
& 'C:\Windows\Microsoft.NET\Framework64\v4.0.30319\csc.exe' /nologo /target:winexe /platform:anycpu `
  /win32manifest:app\app.manifest /r:System.dll /r:System.Windows.Forms.dll /r:System.Drawing.dll `
  /out:app\AiBypass.exe app\AiBypass.cs
```

## Мои ошибки в этой работе

1. **Окно падало при запуске** с кодом `0xE0434352`. Причина: в оконной сборке стоял
   `Console.OutputEncoding = Encoding.UTF8`, а консоли у winexe нет - установка кодировки
   бросает исключение. Исправлено: кодировка ставится только если консоль реально есть
   (`GetConsoleWindow() != 0`), плюс добавлена запись падения в `crash.txt`, чтобы такое
   не было молчаливым.
2. **Проверка адреса и GitHub падали с ошибкой TLS.** Причина: без атрибута
   `TargetFramework` рантайм считает сборку старой и включает TLS 1.0 - GitHub и Cloudflare
   такое не принимают. Исправлено: атрибут `.NETFramework,Version=v4.8` + явные
   `Tls12 | Tls13` в `ServicePointManager` и в `SslStream.AuthenticateAsClient`.
3. **Правила DNS ставились в количестве 1 вместо 8.** В цикле по доменам на каждом проходе
   вычищались «свои» правила - и удаляли то, что добавил предыдущий проход. Исправлено:
   чистка один раз до цикла. Поймано на счётчике правил, а не на глаз.

## 8 ноября 2026, вечер: Gemini нельзя пускать через прокси

Симптом от заказчика: «сайт открывается, но запросы не могут быть обработаны».

Причина — та же, что 16 октября, и она в несогласованности регионов:

| Что | Куда шло | |
|---|---|---|
| `gemini.google.com` (страница) | `217.60.179.6` — Европа | через прокси |
| `geminiweb-pa.clients6.google.com` | `142.250.71.170` — Россия | напрямую |
| `alkalicore-pa.clients6.google.com` | `142.250.198.170` — Россия | напрямую |
| `people-pa.clients6.google.com` | `142.250.71.170` — Россия | напрямую |
| `accounts.google.com` | `64.233.187.84` — Россия | напрямую |

Сервис эти бэкенды **не проксирует** — проверено прямым запросом к их DNS.
Свести к одному региону нельзя: получится «страница из Европы, запросы из России»,
и Google отвечает «не удалось обработать запрос».

Замеры до и после правки:

| Проверка | С прокси | Без прокси |
|---|---|---|
| `gemini.google.com/` | 200 (страница) | **200** |
| `gemini.google.com/app` | — | **200** |
| роутер отдаёт для `gemini.google.com` | — | настоящие `142.251.15x.2` |
| DNS-блокировка Gemini | — | отсутствует, страница открывается с российского IP |

**Что сделано:** Gemini убран из `hosts` (в проге — отдельный статус `DoNotEnable`,
по умолчанию выключен, при ручном включении предупреждает). ChatGPT, Spotify, Grok,
TikTok, Instagram, X, Telegram остались на прокси — 43 домена.

**Аналог «режима полёта» на ПК:** браузер держит свои DNS-кэши и открытые соединения,
`ipconfig /flushdns` их не чистит. Нужно полностью закрыть Chrome (все процессы), затем
`chrome://net-internals/#dns` → Clear host cache и `chrome://net-internals/#sockets` →
Flush socket pools.

**Моя ошибка:** в 1.1.0 Gemini был помечен как «работает» и включён по умолчанию —
потому что проверялся только `gemini.google.com`, а не весь набор доменов, которые нужны
приложению. Проверять надо не одну страницу, а весь набор: страница + бэкенды + вход.
